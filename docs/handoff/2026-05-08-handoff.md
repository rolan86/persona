## 2. What's actually here

### Architecture

Layers, in dependency order. Each has a single public surface; imports flow downward only.

1. `src/paths.ts`, `src/scope.ts` — filesystem paths and scope detection.
2. `src/ingest/**` — Claude JSONL, git log, optional Helix → `Observation[]`.
3. `src/dossier/**` — group `Observation[]` into themed `Dossier`, persist as JSON.
4. `src/synthesize/**` — call LLM with prompt + dossier → typed `Profile`. Two backends:
   - `src/synthesize/claude-code.ts` — shells out to local `claude` CLI (default).
   - `src/synthesize/llm.ts` (the `createAnthropicClient`) — Anthropic API (opt-in).
5. `src/profile/**` — schema, YAML I/O, merge (overrides win), `previous/` rotation.
6. `src/emit/**` — fence parser + deterministic markdown renderer + orchestrator.
7. `src/cli/**` — one file per command (`init`, `status`, `rebuild`, `dossier`, `emit`, `edit`, `diff`, `rollback`).
8. `src/index.ts` — Commander wiring; selects LLM backend via `PERSONA_LLM`.

### Where data lives

A persona scope is global (`~/.persona`, fence in `~/.claude/CLAUDE.md`) or project (`<project>/.persona`, fence in `<project>/CLAUDE.md`). Inside `.persona/`:

- `profile.generated.yaml` — LLM output. Overwritten by `rebuild --yes`.
- `profile.overrides.yaml` — your edits. Merged on top at emit time.
- `dossier.json` — last grouped evidence.
- `previous/profile.YYYYMMDD-HHMM.yaml` — rotated snapshots, last 5 kept.
- `.gitignore` — written by `init`.

### Public commands

| Command | Status |
|---|---|
| `persona init [--scope global\|project] [--share]` | Working. `--share` keeps overrides tracked in git. |
| `persona status` | Working. JSON output. |
| `persona rebuild [--window 90d] [--no-jsonl] [--no-git] [--no-helix] [-y/--yes] [--dry-run]` | Working. **Caveat:** without `--yes` it still calls the LLM and discards the result — see §4 / item I6. |
| `persona dossier [--pretty]` | Working. |
| `persona emit` | Working. Preserves anything outside the `<!-- PERSONA:START v1 ... -->` ... `<!-- PERSONA:END -->` fence. |
| `persona edit` | Prints the overrides path. **Does not yet spawn `$EDITOR`** — see §4 / item I5. |
| `persona diff` | Working. Returns `{ preferences, conventions, rationales }` each with `{ added, removed }`. |
| `persona rollback [--to <substring>]` | Working. Validates the snapshot (Zod) before restore; snapshots current first so rollbacks are reversible. |

### Environment variables

- `PERSONA_LLM` — `claude-code` (default) or `api`.
- `PERSONA_HELIX_DIR` — override Helix sessions path. Default `~/Desktop/Projects/helix/data/sessions`.
- `ANTHROPIC_API_KEY` — only required when `PERSONA_LLM=api`.

## 4. Roadmap (post-v1 follow-ups)

These came out of the final whole-implementation code review (commit `4bfccc3`). They are non-blocking for v1.0-alpha but should be addressed before tagging v1.0-stable. Severity tag is the original reviewer's.

### High priority (real bugs / footguns)

1. **CRITICAL — Widen snapshot timestamps to second-precision.**
   `src/profile/rotate.ts:15` builds `ts` as `YYYYMMDD-HHMM` (12 chars). Two snapshots in the same minute silently overwrite each other. `runRollback` in `src/cli/rollback.ts` works around this by reading `src` bytes into memory before snapshotting `dest`, but the root fix is widening the format. After widening, `rollback` can drop the bytes-cache and use a clean `copyFileSync`.
   Files: `src/profile/rotate.ts`, `src/cli/rollback.ts`, `test/unit/profile/rotate.test.ts` (its hardcoded `profile.20260403-0000.yaml` strings will need updating only if the test asserts on format width — check first).

2. **IMPORTANT — Don't call the LLM on `rebuild` without `--yes`.**
   `src/cli/rebuild.ts:37` runs `synthesize(...)` (which calls the LLM) regardless of `opts.yes`, then prints "Re-run with `--yes` to accept" and discards the profile. This wastes a synthesis call every time. Spec §4.4 calls for a "profile-gate review": write the proposed profile to a temp path (e.g. `.persona/profile.pending.yaml`), show the diff, and only on confirmation rename it into place. Cheaper, less surprising.

3. **IMPORTANT — Profile-gate review needs a real flow, not a one-shot prompt.**
   Tied to #2. Decide whether `--yes` skips the gate or whether the gate is interactive. Current behavior is "non-interactive: dry-print, do nothing." Either is fine, but pick one.

### Medium priority (drift / inconsistency)

4. **Unify `previous/` listing into a single helper.**
   The `readdir + filter('profile.') + sort` pattern appears in three files with subtly different filter predicates: `src/profile/rotate.ts:8` filters `.yaml` suffix; `src/cli/diff.ts:19` and `src/cli/rollback.ts:10` do not. A stray `profile.log` in `previous/` would be picked by diff/rollback and crash inside `loadProfile`. Extract `listPreviousProfiles(previousDir): string[]` and call it from all three.

5. **Remove or wire `state.json` and `autoExpandSuggested`.**
   - `src/paths.ts:34-36` exports `statePath`; nothing reads or writes it. The README originally mentioned it (now removed). Either delete the export or implement state persistence.
   - `src/ingest/index.ts:35` returns `IngestResult.autoExpandSuggested`; no caller reads it. Either surface to the user (e.g., `runRebuild` prints "your window looks sparse, try `--window 180d`") or drop the field.

6. **Real `$EDITOR` launch for `persona edit`.**
   Currently `src/cli/edit.ts:4` is annotated as a deliberate v1 deferral. Spec §5 originally called for spawning `$EDITOR`. Five-line change with `child_process.spawnSync(process.env.EDITOR ?? 'vi', [path], { stdio: 'inherit' })`.

7. **`PERSONA_SYNTH_MODEL` env override.**
   `src/synthesize/llm.ts:9` hard-codes `claude-opus-4-7`. `src/index.ts` doesn't pass any model arg. Add a one-line env read in `createAnthropicClient` and the equivalent in `createClaudeCodeClient` (when claude CLI gains a model flag — check `claude -p --help` first).

### Low priority (polish)

8. **Replace `any` in ingest readers** — `src/ingest/jsonl.ts:14,34,35` and `src/ingest/helix.ts:8,10`. Either narrow Zod schemas at the boundary or `unknown + type guards`.

9. **Helix project-scope cwd filter** — `src/cli/rebuild.ts:68` exempts Helix from the cwd filter because Helix observations don't carry `cwd`. Once Helix carries one, tighten the filter and remove the comment.

10. **Regression test for malformed `profile.overrides.yaml`** — `loadProfile` throws on bad YAML; the test should pin that this propagates to `process.exit(1)` cleanly.

11. **Delete `src/types.ts`** — the barrel re-exports nothing anyone imports. Confirm with grep, then remove.

12. **Guard `init`'s `.gitignore` rewrite** — `src/cli/init.ts:22` always overwrites `.persona/.gitignore`. Re-running `init` stomps user edits. Add `if (!existsSync(...))` guard.

13. **Empty `--dry-run` description** — `src/index.ts` has `.option('--dry-run', '', false)`. Add a real description.

14. **`LLMClient` interface review** — currently `complete(prompt: string)`. The original Task 21 brief assumed `complete({ system, user })`. If we ever want to use claude's `--system-prompt` flag, this becomes a real refactor. Decide: keep the single-string contract (current), or split.

### Nice-to-have

15. **Publish to npm** — `package.json` is ready. Just `npm publish --access public` after picking a non-conflicting name (check `persona` availability; we may need a scope like `@rolan86/persona`).

## 5. Conventions and gotchas worth knowing

- **TypeScript ESM with `"moduleResolution": "Bundler"`.** Source files import siblings with `.js` suffixes (e.g. `from './paths.js'`). Test files use extensionless imports. Both must be respected.
- **Discriminated `Scope` union.** `{ scope: 'global' } | { scope: 'project'; projectRoot: string }`. Never use `as any` — TypeScript narrows spreads correctly.
- **No comments unless the WHY is non-obvious.** Don't narrate what the code does.
- **Commit conventions.** Conventional commits (`feat:`, `fix:`, `docs:`, `chore:`). Direct to `main` (single-branch workflow, recorded in user memory).
- **Subagent-Driven Development.** Each task → fresh implementer subagent → spec reviewer → code quality reviewer → fix loop → commit. Skill at `superpowers:subagent-driven-development`.
- **`init` bypasses `detectScope`.** `src/index.ts:32-39`. This is the one CLI command that constructs `Scope` directly because it's the bootstrap operation. Don't refactor that without preserving the bootstrap behavior — there's no test pinning it (gap; consider adding one).

## 6. Open design questions

- **Per-project vs global precedence.** Current: each scope has its own `.persona/`. No merging across scopes. Should a project rebuild fall back to global preferences? (My read: no — keep them independent; the user can copy-paste statements between overrides files if they want.)
- **Confidence threshold defaults.** `render_threshold` defaults to 0.5 with `>=` comparison. The synthesizer often produces 0.6–0.7 confidence statements. Worth A/B-testing whether 0.5 is too lenient or too strict.
- **Helix integration durability.** Helix is a sibling project of yours; the integration is opt-in via `PERSONA_HELIX_DIR`. If you stop using Helix, the env-var-with-default pattern keeps working — but consider promoting Helix to a real plugin interface so external session sources (e.g., Cursor history, Aider logs) can register the same way.
